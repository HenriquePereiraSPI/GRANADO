Componentes GRD

Catálogo dos componentes de negócio do Granado — web components que já embutem uma regra de chão de fábrica (drill-down de sala/balança, leitura de peso, reentiquetagem etc.), diferente da biblioteca genérica de UI documentada em ComponentsDocumentation.

Os componentes vivem em [AprisoScripts]/WebComponentsGranado/<Categoria>/ e a documentação é organizada em 3 categorias, no mesmo padrão da referência de APIs: Pesagem, Fabricação e Produção.

Regra do espaço GRD: componente GRD não chama API. Ele resolve a interação e devolve o resultado por callback/evento; quem chama a GRD_API_ correspondente é sempre a tela.

Pesagem

<granado-pesagem-reetiquetar-popup>

Popup (overlay modal) de reentiquetagem de saldo — referência ao popup "Reentiquetar Material" da Pesagem › Devolução de MP ao Estoque. Traz um cabeçalho dourado com os dados do material, um drill-down Sala → Balança e o campo Quantidade Pesada, lido da balança pelo 📡 ou digitado no modo Peso manual (com Tara → Peso Líquido).

Segue o padrão dos componentes <granado-box-popup> / <granado-zpl-popup>, com layouts WEB e MOBILE.

Não chama API. O componente devolve o resultado por callback/evento — quem chama GRD_API_JDE_CancelAndGenerateNewLabel (e imprime a nova etiqueta) é a tela.

Import

<!-- Inclua o script no <head> (padrão Apriso) -->
<script src="[AprisoScripts]/WebComponentsGranado/Pesagem/granado-pesagem-reetiquetar-popup.js"></script>

<!-- Opcional: sem ele os avisos de validação caem no alert() nativo -->
<script src="[AprisoScripts]/WebComponents/granado-message-popup.js"></script>

Uso

Forma recomendada (API estática): show() cria o elemento, injeta no <body> e o remove sozinho ao fechar. O peso só entra pelo 📡 — o campo nasce somente leitura até você ligar o Peso manual. 

<script>
  GranadoPesagemReetiquetarPopup.show({
    header: { material: 'Fragância Rosa', lote: 'FRA-2026-04',
              etiqueta: 'ETQ-2026-0421', saldo: '0,498 kg' },
    salas: [
      { id: 'SALA-A', nome: 'Sala A', resourceName: '100000020',
        bals: [ { id: 'BAL-01', cap: '600 kg', sug: true },   // sug: true → ⭐ balança sugerida
                { id: 'BAL-02', cap: '100 kg' } ] },
      { id: 'SALA-C', nome: 'Sala C', resourceName: '100000022',
        bals: [ { id: 'BAL-05', cap: '30 kg' } ] }
    ],
    onConfirm: function (d) {
      // d.salaResourceName → WorkcenterResourceName da GRD_API_JDE_CancelAndGenerateNewLabel
      console.log(d.salaResourceName, d.balancaId, d.pesoLiquido);
    }
  });
</script>

Leitura da balança — onReadScale

O botão 📡 não lê nada sozinho: ele dispara onReadScale(ctx) (e o evento read-scale) e entra em estado carregando (⏳). Quem lê o peso é a tela — normalmente via GRD_API_BeginScaleReadings — e devolve o valor com ctx.setValue(v) (ou el.setPeso(v)), o que também restaura o botão. Sem sala e balança selecionadas o 📡 recusa a leitura com um aviso. 

<script>
  GranadoPesagemReetiquetarPopup.show({
    header: header,
    salas: salas,
    onReadScale: function (ctx) {
      // ctx = { balancaId, salaId, setValue(v) } — o 📡 já está em ⏳
      lerPesoDaBalanca(ctx.balancaId).then(function (peso) {
        ctx.setValue(peso);   // preenche o campo E devolve o 📡 ao normal
      });
    },
    onConfirm: function (d) { console.log(d.quantidadePesada); }
  });
</script>

Peso manual — Tara e Peso Líquido

O toggle Peso manual só destrava depois de escolher a Sala e a Balança. Ligado, ele esmaece o drill-down, esconde o 📡, libera a digitação e mostra os campos Tara e Peso Líquido (líquido = pesada − tara, com tara vazia = 0). Trocar de modo limpa peso e tara — nada vaza de um modo para o outro. Líquido negativo aparece como ⚠ neg. e barra o Concluir. 

<script>
  GranadoPesagemReetiquetarPopup.show({
    header: header,
    salas: salas,
    onConfirm: function (d) {
      if (d.manual) {
        // modo manual: tara informada (vazia = 0) e líquido = pesada − tara
        console.log(d.quantidadePesada, d.tara, d.pesoLiquido);
      } else {
        // modo balança: tara = 0 e pesoLiquido = quantidadePesada
        console.log(d.quantidadePesada);
      }
    }
  });
</script>

Uso — declarativo (HTML)

Também dá para deixar o popup no HTML, iniciar oculto com open="false" e exibir com el.open(), escutando o resultado pelo evento confirm. Atenção: header e salas não têm atributo — são propriedades JS. E close() remove o elemento do DOM, então para reabrir é preciso recriá-lo (o exemplo abaixo faz exatamente isso). 

<!-- header/salas não têm atributo: são propriedades JS -->
<granado-pesagem-reetiquetar-popup id="reet" confirm-text="✓ Concluir" open="false"></granado-pesagem-reetiquetar-popup>

<script>
  var el = document.getElementById('reet');
  el.header = { material: 'Fragância Rosa', lote: 'FRA-2026-04',
                etiqueta: 'ETQ-2026-0421', saldo: '0,498 kg' };
  el.salas  = [ { id: 'SALA-A', nome: 'Sala A', resourceName: '100000020',
                  bals: [ { id: 'BAL-01', cap: '600 kg', sug: true } ] } ];

  el.addEventListener('confirm', function (ev) { console.log(ev.detail); });
  el.addEventListener('close',   function () { /* o elemento já saiu do DOM aqui */ });

  el.open();   // para REABRIR depois do close(), recrie o elemento
</script>

Responsividade — mobile-breakpoint

O popup troca entre os layouts WEB e MOBILE por matchMedia, no limite definido em mobile-breakpoint (default 768). No MOBILE a caixa fica mais estreita, o padding menor e o rodapé vira dois botões de largura total. O exemplo abaixo força o layout MOBILE com um breakpoint alto e ainda liga close-on-backdrop (por padrão clicar fora não fecha). 

<!-- declarativo -->
<granado-pesagem-reetiquetar-popup mobile-breakpoint="900" close-on-backdrop="true"></granado-pesagem-reetiquetar-popup>

<script>
  // via API estática: show() devolve o elemento criado
  var el = GranadoPesagemReetiquetarPopup.show({ header: header, salas: salas, closeOnBackdrop: true });
  el.setAttribute('mobile-breakpoint', '900');
</script>

Integração com a tela (fluxo completo)

Fluxo típico da Devolução de MP ao Estoque: o popup resolve a interação, a tela chama a API e imprime a nova etiqueta. 

<script>
  GranadoPesagemReetiquetarPopup.show({
    header: { material: mat.descricao, lote: mat.lote, etiqueta: mat.etiqueta, saldo: mat.saldo },
    salas: salasDoUsuario,
    onReadScale: function (ctx) { lerPeso(ctx.balancaId).then(ctx.setValue); },
    onConfirm: function (d) {
      // 1) cancela a etiqueta atual e gera a nova (a TELA chama a API)
      chamarApi('GRD_API_JDE_CancelAndGenerateNewLabel', {
        WorkcenterResourceName: d.salaResourceName,
        LabelNoOrigin:          mat.etiqueta,
        LabelQuantity:          String(mat.saldoNumerico),
        LabelWeighedQuantity:   String(d.pesoLiquido)
      }).then(function (r) {
        // 2) r.Data traz o número da nova etiqueta → imprime / atualiza a grid
        GranadoToast.success('Nova etiqueta: ' + r.Data);
      });
    }
  });
</script>

Notas

  • Não chama API: o componente só devolve o resultado. Quem chama GRD_API_JDE_CancelAndGenerateNewLabel — e GRD_API_BeginScaleReadings para o 📡 — é a tela.
  • Drill-down Sala → Balança: clicar numa sala abre as balanças dela; o botão ‹ Voltar limpa a seleção (sala e balança), obrigando a escolher de novo.
  • Modo balança é o default: o campo Quantidade Pesada nasce readOnly — o valor só entra pelo 📡 (ou por setPeso()).
  • Troca de modo limpa os valores: peso e tara são zerados ao ligar/desligar o Peso manual, para nada carregar de um modo para o outro.
  • Tara vazia = 0: deixar a tara em branco no modo manual faz o peso pesado virar o líquido. Líquido negativo exibe ⚠ neg. em vermelho.
  • Números em pt-BR: os campos aceitam vírgula ou ponto; o líquido é exibido com 3 casas e vírgula (0,498 kg).
  • close() destrói a instância: o elemento é removido do DOM. Com show() isso é transparente; no uso declarativo, recrie o elemento para reabrir.
  • confirm-text é a fonte da verdade: o atributo (ou el.confirmText) vale nos dois modos — show({ confirmText }) só o grava no elemento, como em <granado-box-popup>.
  • Avisos: usam GranadoMessagePopup.warning() quando o componente está carregado; sem ele, caem no alert() nativo.
  • Light DOM + inline: sem Shadow DOM e sem stylesheet injetado; cores default hardcoded (paleta Granado).
  • Guard de registro: o arquivo é protegido por if (!customElements.get(...)) — pode ser incluído mais de uma vez sem erro.
